# Reaction Core × v0

How to build new screens for Reaction Core in [v0](https://v0.app) so they land in the app as-is.

## 0. Connecting (v0 / Vercel)

- Repository **AV12am/React**, branch **`claude/vibrant-darwin-dzhvqb`** (`main` holds only the initial commit).
- Framework **Vite** · Build `npm run build` · Output `dist` · Node 20+.
- Environment variables — only if Supabase storage is used: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`,
  `VITE_SUPABASE_BUCKET=vault`. Schema: `deploy/supabase.sql`. Never commit keys.
- Turn on **Deployment Protection** in Vercel: sign-in in the app is still simulated.
- The detailed map reads tiles from your own server (`npm run maps:basemap`); on Vercel it runs in the
  simplified mode. That is expected.

## 1. What is already set up in this repo

| Piece | Where | Why |
|---|---|---|
| Tailwind v4 (scoped, no preflight) | `src/styles/v0-bridge.css` | v0 writes Tailwind; utilities are generated only from `src/v0` and never override the app's own styles |
| shadcn token names → Reaction tokens | `src/styles/v0-bridge.css` | `bg-background`, `text-muted-foreground`, `border-border`, `ring-ring`… render in the matte style and follow the Matte / Paper theme |
| `components.json` | repo root | `npx shadcn@latest add <component or v0 block URL>` installs into `src/v0/ui` |
| `@/` import alias | `vite.config.js`, `jsconfig.json` | v0 imports `@/components/…`, `@/lib/utils` |
| `cn()` | `src/lib/utils.js` | shadcn class helper |
| Base primitives | `src/v0/ui/{button,card,badge}.jsx` | shadcn API, extra `brand` variant (burgundy) |
| Reaction kit | `src/v0/reaction.js` | brand pieces and the classification system for generated code |
| Sandbox | `#/v0` on `npm run dev` | every file in `src/v0/blocks/` is rendered inside the real app shell with live data; not in production builds |

## 2. Workflow

1. In v0, paste the **project instructions** below (Project → Instructions).
2. Generate a block. Use **Add to codebase** → copy the `npx shadcn@latest add "https://v0.app/chat/b/…"` command, or copy the code.
3. Run the command in the repo, or save the code to `src/v0/blocks/<Name>.jsx`.
4. `npm run dev` → open `#/v0` and check it in both themes.
5. When it is right, move it into a view (`src/views/…`) and wire it to the store.

Plain JavaScript (`.jsx`), not TypeScript — `components.json` has `"tsx": false`, so the shadcn CLI converts.

## 4. Classification system for code

`src/data/clearance.js` is the single source of truth — pure data and helpers, safe to import anywhere
(app, server, v0 blocks):

- `LEVELS[0..2]` — `{ id, code, name, gloss, tier, rule, about, download, act }`
- `SEAL` — NON OCULIS HOMINUM
- `docNumber({ level, sealed, year, serial })` → `RC-UMB-2026-0007`; `remark()` re-marks on lowering
- `downgradeState(file)` → `{ to, due, label }`
- `canSeeLevel`, `hasBasis`, `canExport` — the access rules

## 5. Limits

- v0 previews its own sandbox with its own data; what counts is the render in `#/v0`.
- Real enforcement of levels needs the server phase: in this prototype the rules run in the browser.
